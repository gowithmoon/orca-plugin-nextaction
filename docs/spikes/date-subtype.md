# 技术验证：日期属性的 `date` 与 `datetime` 子类型

> 路线图第二步讨论中补测。2026-10-07 在测试笔记库中运行（Windows，时区 UTC+8），共两轮。状态：**已完成**。

## 问题

- 日期属性（`PropType.DateTime`，type 5）的 `date` 子类型能否使用，存成什么格式
- 在 `datetime` 子类型里，"只填日期"和"填了 00:00"能否区分
- 用代码向 `date` 子类型写入带时刻的值，Orca 会不会截掉时刻

## 结论

- **`datetime` 子类型在界面上必须选时刻，不选就是 00:00。** 只填日期（A）和明确选 00:00（B）存出来完全一样，都是本地零点的 UTC ISO 字符串（`2026-10-06T16:00:00.000Z`）。所以笔记里无法区分"只写了日期"和"写了 00:00"。
- 更正（`plugin-panel-writes`）：下面说的"UTC ISO 字符串"是 JSON 打印的结果，`get-blocks` 读回的值是 `Date`，表示的时刻相同。
- **`date` 子类型可用**：`typeArgs: { subType: "date" }`。界面上只填日期，块的 `text` 里只显示日期（`2026-10-07`）。值同样存为本地零点的 UTC ISO 字符串，与 `datetime` 的格式相同。
- **用代码向 `date` 子类型写入带时刻的值，时刻会原样保存，不会被截掉**（D：写入本地 15:30，存为 `07:30:00.000Z`），只是界面和 `text` 里只显示日期。所以插件写入时必须自己传本地零点。
- 值是一个绝对时刻（本地零点），不是"年月日"。在另一个时区的设备上读，按本地日期解析可能差一天。没有实测跨时区，单人使用时不考虑。
- 第一轮脚本的 `setRefData` 第二个参数传了标签名，实际应传引用对象（`BlockRef`），所以报错 `Cannot read properties of undefined (reading 'from')`。第二轮改用 `insertTag` 的 upsert 写入。控制台里 `copy` 不可用，脚本改为 `console.log` 输出。

## 对后续步骤的影响

**第二步：结构定义与编解码（ADR 0012）**
- 开始日期、截止日期都用 `date` 子类型。
- 读取时只取值的本地年、月、日，丢弃时刻，转换成 `domain` 中的日期值；写入时传该日期的本地零点（`new Date(年, 月, 日)`）。

**第三步起：逻辑日**
- 开始日期、截止日期是日期，按逻辑日解释（ADR 0012），由 `domain/time` 统一计算。

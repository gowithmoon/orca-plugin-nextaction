# 技术验证：用户在 Orca 中给任务标签加的属性

> 第十二步开工前。2026-10-12 在测试笔记库中运行，共三次。状态：**已完成**。

## 问题

- 用户在 Orca 界面给任务标签加的各类型属性，定义（`type`、`typeArgs`、`pos`）和任务上的值是什么样子
- 默认值存在哪里，新任务打标签时怎么填入
- 删掉一个属性定义后，任务上已存的值去了哪里；再加回同名同类型的属性，旧值会不会回来

## 结论

### 定义

- **界面加的属性 `pos` 为 `null`**，排在插件属性（`pos` 0–12）之后，`get-block-by-alias` 返回时按属性名的 Unicode 编码排列，与界面显示顺序一致（`tag-operations`：`pos` 为 `null` 时按名字排）。
- 类型与 `typeArgs`：
  - 文本 `type: 1`；数字 `type: 3`；布尔 `type: 4`；块引用 `type: 2`，未设搜索范围时 `typeArgs` 里没有 `scope`。
  - 单选、多选 `type: 6`，`subType` 为 `single` / `multi`。**选项是字符串数组**（`["aaa"]`），不是插件用的 `{ n, c }` 对象。`tag-operations` 当时记的"界面创建的属性用对象格式"与此不符，以本次为准：两种格式都会出现。
  - 日期类 `type: 5`，`subType` 有三种：`date`、`datetime`，以及**只有时刻的 `time`**。
- 默认值写在定义的 `typeArgs` 里：`{ defaultEnabled: true, default: … }`。日期类的默认值可以是 `"now"`；块引用的默认值存的是**块 ID**（`[26]`）。删掉再加回的文本属性 `typeArgs` 为 `null`。

### 值

- 都在任务块对任务标签的那条引用的 `data` 里，与插件属性相同。
- **文本属性的值可能是数字**：在界面上往文本属性里填 `222`，存成了 number `222`。
- 单选是字符串，多选是字符串数组，布尔是 `true`/`false`，数字是 number。
- 块引用的值是引用 ID，经块上 `type: 3` 的引用指向目标，与依赖相同（`tag-operations` A2）。
- 日期类读回都是 `Date`：`date` 为本地零点；`datetime` 为具体时刻；`time` 也是完整的 `Date`，日期部分是填写那天，只有时刻有意义。
- **新任务打标签时，Orca 按定义填入默认值**：`"now"` 的日期填当天本地零点，日期时间、时间填打标签那一刻；块引用的默认值由 Orca 建好 `type: 3` 引用后写入引用 ID（新任务的值为 `[44]`，引用 44 指向块 26）。

### 删除定义

- **删掉定义后，所有任务 `data` 中这一项连同值一起消失**，界面上任务也不再显示这个属性（第二次）。
- 再加回同名、同类型的属性，旧值没有回来（第三次）。

### 块引用候选的搜索（#115 补测，两轮）

- **`query` 的文字条件 `{ kind: 8, text }` 匹配块的 `text`，属性值也在其中**："啊啊啊1"（只在多选值里）、"收集箱"（只在状态值里）都能命中；块引用目标的文字同样能命中（块 75 的"任务1"）。
- **不区分大小写**："SD11F" 命中 `sd11f`。
- **中文单字可以匹配**："测"与"测试"命中的结果相同。第一轮的"时""时间"没有命中，是因为库里没有块含有这两个字（时刻显示为 `19:14`）。
- **不是简单的子串匹配，像是分词后的全文检索**：
  - "任务块"除了命中"这是一个测试任务块"，还命中了"测试镜像块 #任务1"。后者没有连续的"任务块"，只是分别含有"任务"和"块"。
  - 英文单词中间的一段（"dfgv"，取自 `sdffgbgdvbfdgvdsvc`）没有命中。英文前缀能否命中没有测。
- **范围过滤可用**：加上 `{ kind: 4, name: 标签名 }` 后，只剩带这个标签的块。不带文字条件时返回这个标签的全部块，与 `get-blocks-with-tags` 一致。
- 加上"有父块或有别名"后，日记块和孤立块不出现。
- `search-blocks-by-text` 返回的对象用 `get-blocks` 取不到，不使用。
- 镜像块是否会出现在结果里，没有观察到。插件仍按惯例在入口把镜像块换成源块。
- 耗时都在 15 ms 以内（测试库，几十个块）。

## 对实现的影响

- 块引用候选用一次 `query`：范围标签（有时）、`kind: 8` 文字、"有父块或有别名"。它的匹配规则与插件自己的任务搜索（逐词子串匹配，见 #112）不同：英文单词中间的一段搜不到，中文多字词可能多命中。这是 Orca 自己的检索行为，不另做处理。

- 自定义属性在任务属性面板中的顺序跟 Orca 一致：先按 `pos`，`pos` 为 `null` 的按名字。
- 读文本值时，number 转成字符串。插件内置的"备注"同样是文本属性，现在只认字符串，用户在 Orca 里填纯数字的备注会读成空值。
- 读选项名用 `choiceName`，两种格式都认。给自定义属性追加选项时，沿用这个属性已有选项的格式。
- 默认值完全由 Orca 处理，插件不读也不写。
- 删除定义时 Orca 已经清掉了值，插件不需要清理，也不会出现旧值复活。

# 技术验证：状态为空或无法识别的任务能否被"状态为收集箱"的查询找到

> 第四步补测（#37）。2026-10-08 在测试笔记库中运行（Windows，UTC+8），中文任务标签"任务"。状态：**已完成**。

## 问题

收集箱要包含状态为空或无法识别的任务（解码时读作收集箱，`taskFromNotes`）。用查询表达"状态为收集箱"时，这些任务会不会被漏掉。

## 结论

- **`op: 1` 状态等于"收集箱"漏掉了异常任务。** 五个测试任务中只命中"收集箱"和"不写属性"两个；状态值为 `null` 和自定义值"我自己加的"的两个都没有命中。
- **`insertTag` 不传状态时，Orca 写入默认值。** "不写属性"的任务实际存的是"收集箱"（状态属性带 `default: "收集箱"`、`defaultEnabled: true`），所以它不是异常任务。
- **`op: 11`（为空）对单选属性一个都不命中**，连值为 `null` 的任务也不命中。它只在日期属性上可用（`tag-property-query` Q6）。
- `op: 2` 状态不等于"待开始"命中了自定义值的任务，但同样漏掉了值为 `null` 的任务。
- 不加状态条件时五个任务全部命中。
- 结论：查询条件表达不了"状态为空或无法识别"。读取收集箱改为查询全部任务，在内存中按解码后的状态筛选（1000 个任务全量取回约 70 ms，ADR 0007）。

## 对后续步骤的影响

- 读取收集箱（第四步）和其他按状态筛选、又要把异常状态读作收集箱的视图，都在内存中筛选状态。
- 按其他已知状态（待开始、进行中等）筛选的查询不受影响：异常任务读作收集箱，本来就不该出现在那些结果里。

## 测试方法

脚本 `.scratch/spikes/19-inbox-anomalous-status.js`：在 2027-02-02 的日记下建一个容器块，下面五个任务，状态分别为"收集箱"、"待开始"、自定义值、`null`（先写"收集箱"再用 `setRefData` 改成 `null`）、`insertTag` 不传属性。四种查询都加上"有父块或有别名"的条件，只统计这五个块。

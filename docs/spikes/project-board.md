# 技术验证：看板布局用到的 Orca 行为

> 第十一步第四阶段开工前（#166–#172）。2026-10-16 在测试笔记库中运行（Windows，Orca 1.97.1，Chrome 148.0.7778.280，Electron 42.7.0）。状态：**已完成**。撤销的结论在"A 撤销"一节，最后靠在现有的树内拖拽上手按一次撤销来确认。

## 问题

- A（#170）用 `lastChild` 把块移到项目块末尾时的位置和撤销。目标分三种：有子块的块、把深一层的子块提升上来、页面（根级块，有别名）。
- B（#166、#168）插件面板里一个单独允许横向滚动的区域：触控板横滑、Shift+滚轮、拖滚动条、滚动吸附。Orca 会不会拦截这些操作，或触发面板后退。
- C（#166）设置的 `singleChoice` 类型：显示成什么控件、默认值、存的是什么值、改了以后订阅是否触发。
- D（#166）浏览器能力：`cqw`、`container-type`、`scroll-snap-type`、`scroll-padding-inline`、`color-mix`、`writing-mode`、`:has()`、`overscroll-behavior-x`。

## 结论

### A 移到项目块末尾：位置

- 先取回目标块写进 `orca.state.blocks`，再在 `invokeGroup` 里 `moveBlocks(…, "lastChild")`，三种目标都正确：
  - A1：写在外面的块成为有子块的块的最后一个子块。
  - A2：深一层的子块被提升，成为项目块的最后一个子块，原来的父块不再有子块。
  - A3：块成为页面的子块。页面仍是根级块，别名保留。
- 所以"移到项目块末尾"可以直接用现有的 `moveBlocks` 加 `lastChild`，目标是项目块本身，页面项目和块项目一样。

### A 移到项目块末尾：撤销（待第二轮）

- 第一轮从控制台移动三次后，用户在日记面板里按了 3 次 Ctrl+Z，三个块都没有回到原位。
- 移动时活动面板是哪一个没有记录，测试中途活动面板还变过（`iiE2CqkcBJ` → `t2lBC9yoyF`），所以还不能判断原因：是撤销记在了别的面板，还是这种目标真的撤不回去。
- `move-blocks` 64a 用 `core.editor.undo` 撤销、64b 在插件面板里手按 Ctrl+Z，都撤回了。
- 第二轮（`step11-board-2.js`）记下了移动时的活动面板，两次移动时活动面板都是插件面板：
  - U1：移到普通日记块 P，用 `core.editor.undo` 撤销，3 秒内没有回到原位。
  - U2：移到页面，同样没有回到原位。
  - M（手按 Ctrl+Z）作废：脚本有缺陷，那时 X 已经是页面唯一的子块，这次移动什么都没改，"回到原位"不说明任何问题。
- U1 的目标 P 是一个普通块，Orca 移动时不看标签，所以它和 `move-blocks` 64a U1 是同一种情形（移到普通块下面），当时撤销是成功的。可见撤销没成功与"目标是项目块或页面"无关，而是控制台直接调命令的这套写法（或者 Orca 1.97.1）的撤销表现变了。这套写法不经过插件的 `orca-calls`。
- 插件真实的写入路径（`orca-calls` 的 `moveBlocks`）对新目标和对任务目标完全相同，只换了目标块的 ID。所以新目标能不能撤销，就看现有的树内拖拽在当前 Orca 版本下能不能撤销：
  - 在全部任务视图中把一个任务拖到另一个任务上，在插件面板中按一次 Ctrl+Z。
  - 能撤回，就说明新目标也可以，#170 的手动验证清单里照常检查一遍。
  - 撤不回，就是现有功能的回归，另开缺陷处理。
- **2026-10-16 用户确认：全部任务视图的树内拖拽，在插件面板中按一次 Ctrl+Z 能撤回。** 所以经插件写入路径的移动，撤销照常可用，"移到项目块末尾"也一样。第一、二轮控制台脚本撤不回去，只是脚本这套写法的问题，不影响插件。

### B 横向滚动

- 在插件面板的视图（`overflow-x: hidden`）里放一个自己设 `overflow-x: auto` 的横条，触控板横滑、Shift+滚轮、拖滚动条都顺畅，用户确认"非常丝滑"。
  - `wheel` 事件的 `deltaX` 正常到达，没有被 `preventDefault`。
  - 最远滚到 1040px，也就是滚到了底。
- 滚动吸附（`scroll-snap-type: x proximity`）生效，以用户在界面上看到的为准。脚本自己的判断（`snappedToColumn: false`）用错了参照元素，不作数。
- 横滑手势没有触发 Orca 的面板后退：前后的 `panelBackHistory`、`panelForwardHistory` 长度不变。插件面板本身也没有跟着横移。
- 窄档列宽 `calc((100cqw - 26px) * 0.85)` 封顶 260px，在容器宽 584px 时得到 260px，符合预期。

### C `singleChoice` 设置

- 设置页显示为下拉框，选项是 `choices` 的 `label`。
- `defaultValue` 在 `setSettingsSchema` 之后立即生效，读到的值是字符串 `"tree"`。
- 改选后 `settings[key]` 是选项的 `value`（字符串 `"board"`），不是 `label`。订阅随每次修改触发：改了 3 次，触发 3 次。
- 第一轮只加了一项临时设置，插件代码不读它，所以改成"看板"之后打开的仍是层级布局，这是预期的。

### D 浏览器能力

- 列出的能力全部支持（`CSS.supports` 都为 `true`）。

## 对看板布局的影响

- #170："移到项目块末尾"的写入用现有的 `moveBlocks` 和 `lastChild`，目标为项目块，页面项目不需要特殊处理。撤销与现有的树内拖拽相同，先按"A 撤销"一节最后的方法确认。
- #166、#168：看板区单独设 `overflow-x: auto` 加 `scroll-snap-type: x proximity`，不需要拦截 `wheel`，也不需要 `overscroll-behavior-x`。窄档列宽用 `cqw`。
- #166："项目视图默认布局"用 `singleChoice`，`value` 用英文键（`tree`、`board`），`label` 走 `t()`。读到无法识别的值时按层级处理。

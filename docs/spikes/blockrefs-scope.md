# 技术验证：块引用属性的搜索范围

> 第五步验收中补测（2026-10-10，用户提出）。状态：**已完成**。

## 问题

- Orca 的块引用属性可以在属性设置中指定"块搜索范围"（例如某个标签），它存在哪里、存的是什么。
- 标签改名后，这个范围会不会跟着变。

## 结论

- 范围存在属性定义的 `typeArgs.scope` 里，值是**标签名**（字符串），不是块 ID。没有设置时，块引用属性的 `typeArgs` 读回为 `{}`。
- 设成任务标签后，在 Orca 自带的标签属性里给"依赖"添加值时，搜索结果只剩任务。
- **插件在设置中改任务标签名（`renameAlias`）后，`scope` 自动跟着变成新名字。** 插件不需要在改名时改写它。

## 对实现的影响

- 任务标签对齐时，给"依赖"补上 `typeArgs: { scope: 任务标签名 }`（`task-tag-structure`）。按 ADR 0008 只补缺的：已有 `scope`（不管是不是任务标签）一律不动，用户自己改的范围保留。
- 插件停用期间改名，启动时先 `renameAlias` 再写定义（同一个 `invokeGroup`）：已有范围由 Orca 跟着改名；原来没有范围的，按新名字补上。
- 插件自己的依赖候选搜索不经过这个范围，不受影响。
- 没有实测：在 Orca 中把范围清空后存的是缺项还是空字符串。缺项时下次启动会被补回任务标签；空字符串会保留。

## 验证代码

`.scratch/spikes/53-blockrefs-scope.js`（不纳入版本管理）：读出任务标签上全部属性的定义并打印。共运行三次：不改设置；在 Orca 中把"依赖"的块搜索范围设成任务标签；在插件设置中把任务标签名改成"任务2"。

## 实际返回（"依赖"一项）

| 时机 | `typeArgs` |
|---|---|
| 未设置范围 | `{}` |
| 范围设为任务标签"任务" | `{ "scope": "任务" }` |
| 插件设置中改名为"任务2" | `{ "scope": "任务2" }`（标签别名同为 `["任务2"]`） |

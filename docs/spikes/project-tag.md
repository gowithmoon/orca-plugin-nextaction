# 技术验证：项目标签与任务标签并存、所属项目的块引用

> 第十一步第一阶段开工前。2026-10-15 在测试笔记库中运行一次，只用两个测试标签"NA任务验证""NA项目验证"。状态：**已完成**。

## 问题

- 一个块同时打两个标签时，两份属性值怎么存放；查询、界面显示、标签菜单是否互不干扰；移除其中一个标签，另一个的值是否还在
- 块引用属性能否设成单值；搜索范围设为项目标签后，Orca 的候选列表里有什么
- `insertTag` 能否在打标签时直接用块 ID 写入块引用值（快速捕获要一次带上所属项目）
- 右键同一个块上的两个标签时，标签菜单收到的 `tagBlock`、`tagRef.from`

## 结论

### 两个标签并存

- **两份值各自独立**：块上有两条 `type: 2` 的标签引用（`_tags` 为 `[53, 54]`），各自的 `data` 只有自己标签的属性，同名属性（两边都有"状态"）互不影响。
- 按标签查询各自命中：按任务标签查到 B，按项目标签也查到 B。
- 界面上两个标签都正常显示（用户确认）；各自的 `.orca-tag` 带自己的 `data-name` 和 `data-状态`，状态图标的选择器按标签名区分即可。
- 标签菜单：右键任务标签，`tagBlock` 是任务标签块（88）；右键项目标签，`tagBlock` 是项目标签块（87）；两次的 `tagRef.from` 都是 B（93）。现有的任务操作菜单已按 `tagBlock.id` 过滤，项目操作菜单照此做即可。
- `removeTag` 移除项目标签后，任务标签那条引用和它的值原样保留，`text` 中只少了项目标签那一段。
- 打项目标签时 Orca 按定义填入默认值（状态"规划中"、重要性 4）；没有默认值的"目标"不出现在 `data` 中。

### 所属项目（块引用）

- **在界面上添加的值与依赖相同**：值是引用 ID（`[55]`），引用 55 是任务块到项目块的 `type: 3` 引用；项目块的 `backRefs` 里有它（`tag-operations` A2、`next-action-hierarchy-boolean-deps`）。
- 任务的 `text` 中带上了项目块的文字（`#NA任务验证,P 测试项目,收集箱`），所以搜索项目名能搜到靠所属项目归属的任务（第十二步的搜索规则）。
- 搜索范围 `typeArgs.scope` 设为项目标签名后，候选列表只有带项目标签的块（"P 测试项目"和同时带两个标签的"B 两个标签"）。
- **单值没有验证到**：属性已经有值时，Orca 不允许改它的类型设置（用户反馈），没看到是否有单值选项。插件不依赖它，按自己的规则只取一个值，见下文。
- **`insertTag` 不能直接写块引用值。** 传 `{ name: "所属项目", type: 2, value: [块ID] }` 或不带 `type`，都把块 ID 原样存进了 `data`（`[89]`），但没有建 `type: 3` 引用：项目块的 `backRefs` 里没有它们，`text` 里也没有项目名。这个值会被当成引用 ID 解读，而引用 ID 会被回收再用（`tag-operations`），日后可能指向别的块。`Backend-API.md` 说 `props` 里块引用可以是块 ID 数组，那是后端接口的说法，不适用于 `insertTag` 编辑器命令。

## 对实现的影响

- 项目标签的读取找 `to` 为项目标签块的那条 `type: 2` 引用，与任务标签相同；同一个块上两个标签的值不会混淆。
- 所属项目的读写复用依赖的做法：读时经 `type: 3` 引用把引用 ID 解析成块 ID，解析不到的视为没设；写时先 `createRef(任务, 项目, 3)`，再 `setRefData` 写引用 ID（`runRefDataWrite`）。
- 快速捕获带所属项目时，`insertTag` 只写其他初始属性，所属项目在同一个 `invokeGroup` 里再按上面的方式写入，一次撤销。没有测这一组合的撤销，开工时按第三步 `capture-initial-properties` 的方式补测。
- 所属项目按单值处理：读时有多个值只取第一个，插件写入时只写一个。用户在 Orca 界面里加了第二个值时，插件忽略它，不报错。
- 放弃项目时，靠所属项目归属的任务从项目块 `backRefs` 中的 `type: 3` 引用找到，再用任务的所属项目值是否含这个引用 ID 确认，与放弃任务清除依赖相同。
- 没有测：撤销；镜像块上的项目标签；项目标签改名后 `scope` 是否跟随（任务标签上已验证跟随，`blockrefs-scope`，预期相同）。

## 验证代码

# 拖到笔记的写入经过落点所在的笔记面板，撤销记在那里

把任务卡片拖到笔记时，写入（行内引用、只有引用的新块、镜像块）不走插件面板里藏起来的编辑器（ADR 0014），而是先把焦点切到落点所在的笔记面板，再通过它的编辑器写入。所以撤销记在这个笔记面板里，用户在那里按 Ctrl+Z 撤回，就像自己在笔记里打字一样。原因是行内引用要用落点的光标（`CursorData` 属于那个笔记面板），而且拖放的结果出现在笔记里，用户的注意力也在那里。时序由实测确定（`docs/spikes/drag-to-note.md`）：松开后等约 100 ms 再切焦点，否则插件面板会把焦点抢回去，组里的命令被分记到两个面板上；切焦点后再等约 100 ms 再写，否则 Orca 恢复面板上次的光标，会盖掉写入放的光标。这条写入路径仍在 `infra/orca/orca-calls.ts` 里，用编辑器命令和 `invokeGroup` 写入，不用后端接口。

## Considered Options

- 经过插件面板的隐藏编辑器写入，撤销留在插件面板（ADR 0014 的做法）：未采用。行内引用需要笔记面板的光标；即使块级写入能从插件面板写，用户也得回到插件面板才能撤销，而拖放的结果在笔记里。
- 弹出菜单让用户选择引用或镜像，像 Orca 自己的拖块那样：未采用。Orca 没有给插件开放拖放钩子，它原生的四项菜单借不到；而引用远比镜像常用，多一步操作不值得。改为默认引用，按住 Alt 写镜像。

## Consequences

- 两个 100 ms 是实测值，不是 Orca 的约定。Orca 升级后要复查；失效时的表现是一次撤销只撤掉一半，或者写完后光标跳到别处。
- 镜像块用 `batchInsertReprs` 加 `createRef(…, 5)` 建，才和 Orca 界面建的一致。用 `insertBlock` 传镜像 `_repr` 建的块，会让 Orca 全局搜索多出一条结果。

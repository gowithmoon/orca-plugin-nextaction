# 依赖重复任务只看它的状态

依赖是否满足只看被依赖任务的状态，被依赖任务是重复任务时也一样。重复任务每完成一次就进入下一次、回到待开始，所以依赖它的任务在它的重复规则关闭（结束条件到达，或用户关闭规则）之前一直处于依赖阻塞。插件允许添加这样的依赖，但在任务属性面板选择被依赖任务时，对重复任务给出提示，说明这条依赖要到它不再重复、最终完成时才满足。参照 MyLifeOrganized：它的行为相同，但不给任何提示，任务会无声地卡住。

## Considered Options

- 被依赖的重复任务有过任意一条完成记录就算满足，依赖延迟从最后一条完成记录起算：被否决。依赖的含义从"它完成了"变成"它完成过"，与普通任务不一致；重复任务下一次还没做，依赖它的任务却一直放行。
- 按"本次之前完成过"判断（最后一条完成记录晚于依赖方上一次进入下一次的时刻）：被否决。要引入"第几次"的概念，规则难以向用户解释，也没有真实场景要求它。
- 不允许依赖重复任务：被否决。"等这个重复任务最终结束"是合理需求，而且任务在添加依赖之后才被设为重复时，仍要处理已有的依赖。

## Consequences

- 想要"重复任务每完成一次，另一件事出现一次"，用子任务表达：进入下一次时，没有自己重复规则的已完成后代任务一并回到待开始。
- 跳过不改变状态之外的任何判断，自然也不满足依赖；ADR 0018 的依赖延迟计时照用，只看完成记录。
- 同样的规则也适用于块层级：重复子任务永远不处于已完成，它的父任务一直处于子任务阻塞；在顺序执行的父任务下，它一直挡住排在后面的子任务。接受这个结果，不把重复子任务当作不存在；任务属性面板对顺序执行下的重复子任务给出提示。
- 依赖延迟遇到被依赖的重复任务时，起算日是它最终完成那一次的完成记录。

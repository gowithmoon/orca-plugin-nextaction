# 插件面板覆盖相邻面板，而不是再挤进一个窄面板

插件面板在全局最多只有一个。当前这一行只有发起面板时，在它右侧新开插件面板，两者对半分。已经有两个及以上面板时，不再新增面板，而是用 `nav.goTo` 把与发起面板相邻的面板（只限 `block` 和 `journal` 视图）换成插件面板，并把被覆盖面板的视图和参数存进插件面板；用户再次点击按钮或插件卸载时，用 `nav.replace` 恢复原内容。之所以这样做，是因为第三个面板会被挤得很窄，插件面板的可用性会受影响。

## Considered Options

- 新增一个面板，只把发起面板一分为二：实测可行（`docs/spikes/editor-sidetool-panel.md`），但用户认为插件面板仍然太窄，否决。
- 使用 Orca 默认的均分：三个面板各占三分之一，同样太窄，否决。

## Consequences

- 用户用 Orca 自己的方式关闭插件面板，或者重启 Orca 时，被覆盖面板的原内容不会恢复：那个面板没了，但日记和块本身不受影响，重新打开即可。用户已接受这个代价（2026-10-07）。
- 传给导航 API 的 `viewArgs` 必须保持原始类型，传错会让整个 Orca 崩溃。所以只覆盖参数结构已知的 `block` 和 `journal` 视图，其他视图一律改为新开面板。
- 用 `goTo` 覆盖会留下一条后退历史，用户在被覆盖的面板上点后退，也能回到原内容。

# 任务标签的数据结构只增不改

插件每次启动时都把任务标签"对齐"到当前版本期望的结构：缺少的属性、选项和默认值会补上。对齐只增加，不删除、不改名、不改类型，而且可以重复执行，结果不变。破坏性变更一律不做；确有必要时，单独设计一个由用户手动触发的迁移命令。

## Considered Options

- 在 `plugins.setData` 中记录已执行的迁移，允许自动执行破坏性迁移：被否决。`setData` 是否随笔记库同步无法确定，换一台设备时迁移可能重复执行，而且失败后很难恢复。

## Consequences

- 对齐时遇到用户自己加的属性或选项，原样保留，不影响接管。任务的状态被设成插件不认识的选项时，该任务视为处于收集箱；只是标签上多了这个选项，不影响任何任务。
- 同名属性的类型或子类型与插件的定义不同时，对齐无法修复它。插件第一次接管一个已有的同名标签（本机没有它的缓存）时，遇到这种冲突就不接管，通知用户在设置中换一个名字；已经接管的标签出现这种冲突时，只有这个属性失效（读作空值，写入时报错，按它筛选时报错），其他功能照常，每次启动通知一次，直到冲突解决。

# 我的一天记录按逻辑日保留，过去的记录不再改动

每个任务的我的一天记录存在插件块属性 `nextaction.myday` 中，形如 `{ v: 1, entries: [{ day, start?, end? }] }`：`day` 是逻辑日（`YYYY-MM-DD`），`start`、`end` 是排期的绝对时刻（ISO 字符串，读回时是 `Date`），最早的在前，每个逻辑日最多一条。插件只增删、修改今天的那一条；过了日界线，那一条就成为过去的记录，原样保留，不再改动，也不顺延。之所以不在新的一天覆盖或清理，是为了给以后的日历视图和统计留下"哪天做了什么"的数据，而这份数据只有当天能记下来，事后无法补回。

## Considered Options

- 每个任务只存一条，过了日界线就失效、再次加入时覆盖（GLOSSARY 原来的写法）：被否决。格式最简单，但过去的安排一去不回，以后要做日历视图就得另起一份数据。
- 读取或写入时顺手清理过期记录：被否决。会把用户没做过的修改塞进撤销历史。
- 排期存距日界线的分钟数（思源版的做法）：被否决。日界线一改，所有排期整体平移；绝对时刻不受影响，落到当天范围之外的排期显示为未排期。
- 新记录加在最前面：与加在末尾没有复杂度差别（Orca 每次整体重写属性值），选末尾是为了与完成历史一致。

## Consequences

- 属性值随使用天数增长：每条约 80 字节，天天加入十年约 290 KB。到需要时再考虑上限，现在不设。
- 移出我的一天是删掉今天那一条，历史只记"那天在我的一天里"，不记加入、移出的反复。
- 复制任务会连同全部记录一起复制，副本当天就出现在我的一天中（`block-properties-json`）。接受这个结果，与完成历史的同类问题留到第八步一起考虑。
- 放弃任务删除全部 `nextaction.*`，它的我的一天历史随之丢弃，一次撤销可以恢复。

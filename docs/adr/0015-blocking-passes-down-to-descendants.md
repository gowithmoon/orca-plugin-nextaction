# 依赖阻塞和顺序阻塞向后代任务传递

一个任务被依赖阻塞或顺序阻塞时，它的全部后代任务也处于阻塞；开始日期同样向下约束，真正起作用的是任务自己和全部祖先任务中最晚的开始日期。子任务阻塞只向上，不向下传递，否则父任务和子任务会互相锁死。这样，"P 要等 X 完成"或"P 排在 A 之后"对 P 下面拆出来的每一步都成立，用户不必给每个子任务再设一遍。

## Considered Options

- 阻塞只看任务自己（思源版 `siyuan-plugin-nextaction` 的做法）：被否决。父任务被依赖阻塞时，它的子任务照样出现在下一步行动里；顺序执行的父任务下，排在后面的子任务里嵌套的任务也照样出现。拆分得越细，依赖和顺序执行就越失效。

## Consequences

- 循环不再只是依赖之间的环：父任务依赖自己的后代任务、后代任务依赖祖先任务、顺序执行中排在前面的任务依赖排在后面的任务，都会让任务永远无法成为下一步行动。循环检测把三种阻塞统一成一张"谁在等谁"的图来判断。
- 判断一个任务是否阻塞，要沿块层级向上看全部祖先任务，不能只读任务自己的属性。

# 标签取代标记

任务不再有"标记"这个内置属性，原来用标记的地方（任务卡片、任务属性面板、下一步行动和全部任务的筛选、统计的完成的分布）改用任务块上的 Orca 标签，不含任务标签和项目标签。插件只读标签：面板和卡片上只显示，不能添加或移除，也不能点击跳转；要改就在 Orca 里打标签。只看块上直接打的标签，不继承，不展开标签的包含关系。项目不显示标签。

理由：标记和 Orca 标签做的是同一件事（用户自定义的、多值的分类），两套并存时用户要记住哪个是哪个，在 Orca 里打的标签插件看不到，在插件里填的标记 Orca 的标签体系里也没有。只保留 Orca 标签，术语和用户的笔记习惯都只剩一套。

## Considered Options

- 面板里可以添加、移除标签：被否决。加标签就要在插件里选已有标签、新建标签，重做 Orca 已有的入口；写标签也会让面板的写入多一类撤销步骤。
- 把已有的标记值迁移成同名的 Orca 标签：被否决。插件尚未正式发布，没有要迁移的用户数据；迁移本身又要批量改写块、新建标签，难以撤销，违背 ADR 0008 只增不改。
- 上下文也换成标签（例如 `@` 开头的标签）：被否决。上下文是 GTD 的核心维度，取值少、含义固定，靠命名约定从标签里分出来容易出错。
- 按标签的包含关系展开（按父标签筛选时带上子标签）：被否决。和"只看块自己的"不一致，包含关系的数据形态也未实测。

## Consequences

- 插件不再把"标记"/"Label"当作内置属性。已经带着这个定义的任务标签（开发期间的笔记）上，定义和值都保留（ADR 0008），按 ADR 0023 成为一个多选的自定义属性，不参与筛选和统计；不需要时在 Orca 里删掉这个定义。
- 之后新建的任务标签不再带"标记"，内置属性的位置因此前移一位；已有任务标签上的位置不变。
- 读任务时要列出块上全部的标签引用，去掉任务标签和项目标签，而不只是找任务标签那一条。
- 筛选里列出的标签，是现有任务上出现过的标签，不是 Orca 里的全部标签。

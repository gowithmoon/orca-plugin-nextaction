# 常设排期带进我的一天的任务靠计算得出，不写进我的一天记录

重复任务可以设一个常设排期（GLOSSARY），例如工作日的晨会 8:45–9:15。读取我的一天时，插件把今天该做、今天又没有我的一天记录的这类任务算进来，按常设排期的时段显示，笔记不变。用户对它做了操作才写入，这些写入本来就是用户的操作：拖动或改时段、移回未排期时，写一条今天的我的一天记录，之后以这条记录为准；移出时，在常设排期上记下"今天已移出"，当天不再带进来；当天又加回来时清掉这个标记，它回到常设时段。我的一天记录的格式和含义不变（ADR 0020），移出仍然只是删掉今天那一条。

常设排期存的是一天中的时刻，不是绝对时刻，所以不受夏令时影响。早于日界线的时刻算在逻辑日的末尾。跨过日界线的时段不能保存；用户事后改了日界线、使时段跨过日界线时，那几天显示为未排期，常设排期不动。

## Considered Options

- 打开我的一天视图时，替用户写入今天的记录：被否决。理由和 ADR 0016、0020 否决"读取时写入"相同：这次写入会进入撤销历史，用户打开视图后按 Ctrl+Z，撤回的是一次他没有做过的写入。读取时也不一定有可写的编辑器（ADR 0014）。
- 跨过日界线时由监听器写入：被否决。撤销历史的问题同样存在；Orca 没有运行时不会触发，还要多一个常驻的监听器。
- 把时段并进重复规则：被否决。重复规则管哪几天，常设排期管当天几点，二者互相独立；合进去会让规则更复杂，暂停重复、改规则时也说不清时段的去留。
- "今天已移出"记成一条带标记的我的一天记录：被否决。记录的含义会从"那天在我的一天里"变成两种，以后的日历视图和回看过去都得认识它。

## Consequences

- 没被用户动过的那些天不留下我的一天记录。回看过去不列出这些任务；没做的那一次日期停在过去，会作为逾期任务出现在回顾中。以后做日历视图时，查不到那些天"排在几点"，只能从完成历史看出那天做了。
- 读取我的一天要在读记录之外，再按常设排期、日期、完成历史算出带进来的任务；选择可加入任务时，这些任务算作已在今天的我的一天中。
- 去掉重复规则（包括到了结束条件）时，常设排期在同一次写入中一并去掉，不留下不起作用的属性。将来要让非重复任务也能用，要先改这条。
- 常设排期随复制任务一起复制，放弃任务时随 `nextaction.*` 一起删除，与 ADR 0020 对我的一天记录的处理一致。

# 视图按需查询，不维护全局实时索引

Orca 没有全局的"块已修改"事件，`orca.state.blocks` 也只包含已加载到内存里的块。因此视图采用按需查询，加上会话内的短期缓存：插件自己写入数据后，立即让相关缓存失效；视图打开、获得焦点或用户手动刷新时重新查询；对内存中已加载的块订阅变化，尽量及时刷新。由此带来的后果是，用户直接在编辑器里修改任务后，已经打开的视图可能要到下一次获得焦点时才更新。这个延迟是可以接受的。

## Considered Options

- 在内存中维护全量任务索引，并拦截编辑器命令来保持同步：被否决。这种做法会侵入 Orca 的命令系统，覆盖不全，而且容易和 Orca 的升级冲突。

## Consequences

- 任务索引是 `infra` 层接口背后的一个实现。以后如果找到可靠的变更信号，可以直接替换实现，上层代码不用改。

# 任务身份只由插件的任务标签决定，标签按名称识别

一个块是不是任务，只看它有没有插件管理的任务标签，与 Orca 原生任务块（复选框 `makeTask`/`toggleTask`）无关。插件按设置中的名称找到任务标签，不在标签块上写任何身份标记。默认名称按第一次启动时的界面语言取"任务"或 "Task"，并立即写入设置，此后不随界面语言变化。插件启动时如果找不到这个标签，就创建它并补齐标签属性和默认值；用户在插件设置中改名时，插件用 `core.editor.renameAlias` 重命名已有标签，不新建也不删除。

## Considered Options

- 只用原生任务块识别任务：原生任务块只有完成/未完成两态，无法承载 GTD 的状态和属性。
- 以插件标签为准，同时与原生复选框双向同步：被否决。两份状态、两个入口，谁覆盖谁难以定义，是缺陷高发区。与原生复选框的联动以后可以作为单向的可选适配器加入。
- 在标签块上写隐藏的块属性作为身份标记：被否决，因为希望标签上保持干净。

## Consequences

- 改名只支持在插件设置中进行。用户如果在 Orca 里直接修改任务标签的别名，下次启动时插件会找不到标签，并新建一个同名于设置的标签，原有任务不再被识别。用户文档必须写明这一点。
- 插件在 `plugins.setData` 中缓存上次成功使用的任务标签块 ID 和名称（可丢弃、可重建，符合 ADR 0001），只用来补救改名：插件停用或加载失败期间用户在设置中改了名，下次启动时，如果缓存的块仍是叫旧名字的标签，就补做一次 `renameAlias`，不新建标签。`plugins.setData` 和插件设置都按笔记库保存（`docs/spikes/plugin-lifecycle-settings.md`），所以每个笔记库有自己的任务标签名和缓存。缓存丢失（例如换了设备）时退回按名称识别。
- 设置中的新名字不合法（为空，或已被其他块占用）时，不改名，把设置改回原来的名字并通知用户。

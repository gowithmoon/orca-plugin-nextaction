# 提醒由插件自己实现，不复用 Orca 原生提醒

提醒由插件自己存储、计时并发出系统通知，不使用 Orca 的 `Reminder` 标签。一个任务的全部提醒存在任务块的插件块属性里（ADR 0001）；Orca 运行时，插件只为最近的一个提醒设一次 `setTimeout`，到时再读一次任务，已完成或已不是任务就不通知；通知用渲染进程的网页 `Notification` 发出。原生提醒做不到一个任务有多个提醒：一个块只能挂一个 `Reminder` 标签，只有一份 `Date time`，`Repeat every` 和 `Cron` 只能表达有规律的重复，表达不了"截止前三天和当天各提醒一次"。

## Considered Options

- 复用原生提醒，在任务块上打 `Reminder` 标签：被否决。只能有一个时刻；通知内容是块文本，带出 `#Reminder` 和任务标签；在 Orca 里直接改成已完成的任务仍会被提醒。它的长处是 Orca 关闭后重新打开会不会补发、点击通知能定位到块，都由 Orca 负责。
- 每个提醒建一个带 `Reminder` 标签的子块：被否决。笔记里多出一批提醒块，全部任务视图、顺序执行、子任务阻塞这些按块层级计算的地方都要把它们排除，通知内容也成了子块的文字而不是任务。
- 用 `setInterval` 轮询：被否决。Orca 隐藏后实测被节流到每分钟最多一次；单次 `setTimeout` 最小化 12 分钟只晚 142 ms（`docs/spikes/native-reminder.md` 第十步补测二）。

## Consequences

- Orca 没有运行时提醒不了。"检查到哪个时刻"记在 `plugins.setData`（可丢弃）；下次打开时，把这个时刻到现在之间、仍未完成的任务的提醒逐个补发；记录丢了就从当前时刻算起，不补发。
- 两台设备同时开着 Orca 时，两边都会提醒；复制任务块时提醒跟着复制，到时会有两条同名通知。都不处理。
- 任务块上已有的原生 `Reminder` 标签，插件不读、不改、不迁移，Orca 照样按它提醒。
- 点击通知时，插件在 Orca 没有焦点时调 `core.global.toggleWindow` 把它带到前台，再定位到任务块（补测五）；通知收进系统通知中心后再点，网页 `Notification` 收不到点击，这时什么都不做。

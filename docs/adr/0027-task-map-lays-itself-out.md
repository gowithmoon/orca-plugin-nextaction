# 任务全景图自己算布局，不保存坐标，不用布局库

任务全景图中卡片和框的位置每次都由插件按任务关系现算：逐个容器自下而上分层，同层按笔记中的顺序，跨容器的依赖只用来决定左右先后；连线由插件自己画成曲线，不为它们绕开别的框。位置不保存，也不能手动调整，拖卡片只表示移动任务。布局代码写在插件里，不引入 elkjs 之类的布局库。

理由：关系一改位置就该跟着变，保存坐标既要找地方存（块属性会弄脏笔记），又会在关系改变后变得说不通，还和"拖卡片移动任务"争同一个手势。实测中 elkjs 在 Orca 里太慢：200 个任务一次排整张图要 1–3 秒，逐个容器排也要半秒左右，800 个任务又到 12 秒，而每次写入后都要重排；自己写的简化分层布局 800 个任务约 4 毫秒，放在主线程即可，也省掉了 1.6 MB 的库、Worker 和分块加载。代价是交叉多一些、长连线会穿过别的框，靠选中后高亮上下游来看清。

## Considered Options

- elkjs 一次排整张图（`INCLUDE_CHILDREN`，含正交走线）：排得最好，但在 Orca 中 200 个任务要 1–3 秒，主线程会卡住 Orca。
- elkjs 逐个容器排（`SEPARATE_CHILDREN`，依赖抬升为代理边）放进 Worker：快 3–8 倍，仍要 0.4–1.3 秒，任务多时又到 12 秒；还要按需加载分块和 Worker（实测可行）。
- 自动布局加手动微调并保存坐标：见上面的理由。

实测见 `docs/spikes/task-map-elk.md`。

# 失效依赖只在插件自己的写入中清除

被依赖的块已不是任务时（被删除成孤立块、被放弃、任务标签被移除），这条依赖在规则上始终视为已满足；但笔记中的依赖值只在插件自己的写入里顺带清除：放弃任务时，在同一个 `invokeGroup` 中清除指向它的依赖；编辑一个任务的依赖时，清除它自己的失效依赖。用户在 Orca 中直接删除块留下的失效依赖，会一直留在笔记里，直到下一次这样的编辑。Orca 自己不会清理失效依赖（`docs/spikes/tag-operations.md`）。

## Considered Options

- 读取视图时发现就清除：被否决。清除是一次写入，会进入用户的撤销历史：用户打开视图后按 Ctrl+Z，撤回的是一次他没有做过的清理，而不是自己刚才的编辑。读取还可能发生在没有可写编辑器的时候（ADR 0014）。

## Consequences

- 读取任务时必须能分辨失效依赖，不能假设笔记中的依赖都指向任务。任务属性面板把它们标为"已失效"。
- 清除依赖后，被删除的块作为孤立块留在笔记里，没有任何引用。插件不替用户删除它：判断孤立块的规则一旦误判，删掉的就是用户的块。孤立块已被所有任务查询排除，不会出现在视图中。

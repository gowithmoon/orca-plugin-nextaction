# 澄清

捕获下来的任务都在收集箱中，澄清就是逐个决定它们如何处理：要不要做、什么时候做、属性怎么设置、需要拆成几步。

## 在收集箱里处理

打开「收集箱」视图，任务按捕获的先后排列，最早的在最上面。点一张卡片打开任务属性面板，然后做出决定：

| 决定 | 怎么做 |
|---|---|
| 要做 | 状态改成待开始，按需要补上重要性、截止日期等属性 |
| 已经在做 | 状态改成进行中 |
| 要等外部条件 | 状态改成等待中 |
| 未来可能要做 | 状态改成将来/也许 |
| 不做了 | 放弃 |
| 已经做完 | 状态改成已完成 |

## 任务拆分

当一个任务较大时，推荐进行任务拆分，拆分成多个最小化的子任务：

- 手动拆分：在任务操作菜单里选「新建子任务」，逐个新建。也可以直接在笔记里，在任务块下面写子块，再逐个转为任务。
- AI 拆分：在任务操作菜单里选「拆分子任务」。若有不确定的地方，AI 会先询问一些问题，然后给出草稿，你可以进行调整并确认写入。

AI 认为任务已经足够小时，会直接告诉你不必再拆分。

## 澄清建议完善的属性

- 截止日期：只有任务真的有完成期限才设置，随手设置的截止日期会让真正紧急的事被淹没。
- 开始日期：现在还做不了的任务，设上开始日期，到那天之前它不会出现在下一步行动里。
- 上下文：只能在特定场景做的事，比如只能在公司做，加上对应的上下文。
- 所属项目：属于某个项目的任务，设好所属项目，或者把它移到项目块下面。

属性的含义见[任务属性](05-task-properties.md)。

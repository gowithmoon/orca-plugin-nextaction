# 路线图

按顺序推进，不设版本号。完成第五步后开始个人日常使用，之后在使用中迭代；准备好了再走第十六步对外发布。每一步开始前，先拆成 GitHub Issues；每一步的细节设计在开始时单独讨论。

插件的核心能力与步骤的对应关系见文末。

---

## 第一步：工程地基（已完成）

**目标**：把规矩落实成代码和工具，此后的每一步都在这个骨架上添加内容。

- 按 `docs/ARCHITECTURE.md` 建立目录结构，`main.tsx` 只负责转调。
- 实现注册表（`unload` 时按逆序释放）、`Clock` 端口、`shared/l10n`。
- 接入 Vitest、Biome、架构测试、翻译完整性测试，锁定依赖版本，收紧 tsconfig。
- 配置 GitHub Actions。
- **技术验证**（已完成，2026-10-07，结论见 `docs/spikes/README.md`）：查询、标签操作、块属性 JSON、编辑器工具按钮与面板、状态图标与菜单、日记捕获、原生提醒、块变更信号、插件生命周期与设置。实测结论已回写到 `docs/ARCHITECTURE.md` 第 4 节"Orca 行为约束"、ADR 0007 和 ADR 0011。

**完成标准**：空插件可以加载、卸载，卸载后不残留任何东西；CI 全部通过；技术验证结论已归档。

## 第二步：任务标签与数据层（已完成）

**目标**：插件能够可靠地读写任务。

- 任务标签的结构定义：启动时创建并对齐属性、选项和默认值；在设置中改名时调用 `renameAlias`。
- 属性名和选项名的中英文名称表，以及编解码（ADR 0009）。
- `domain/task`：`Task`、六种状态、各属性的值对象。
- `TaskRepository`：按 ID 读取、按条件查询、写入属性、写入插件块属性。镜像块在入口统一解析成源块，任务查询排除孤立块。
- 用真实 Block 样本建立测试夹具。

**完成标准**：编解码测试覆盖中英文名称和异常数据；在 Orca 中改名后，已有任务仍能被识别。

## 第三步：捕获与状态流转（已完成）

**目标**：可以把想法变成任务，并推进它的状态。

- 转为任务命令：把光标所在的块转为任务（打上任务标签，状态为收集箱）。插件只注册命令，不分配快捷键，由用户自己绑定。
- 快速捕获：用命令（用户绑定的快捷键）打开弹窗，新任务追加到当天（自然日）日记末尾。
- 放弃（移除任务标签，同时删除插件块属性），在任务操作菜单中执行。
- 任务完成时记录完成历史。
- 日界线设置与 `domain/time`（逻辑日）。
- 状态标识：任务块前显示表示当前状态的图标，只用于显示。
- 任务操作菜单：右键点击任务标签，或在任务块手柄上右键，在 Orca 自带的菜单里切换状态、打开任务属性面板，以及执行其他任务操作（如放弃）。菜单中的操作项通过统一的登记方式添加，后续步骤（如加入我的一天）往里追加即可。

**完成标准**：不打开插件面板，也能完成捕获、改状态、放弃的全过程，并且都可以撤销。转为任务和快速捕获通过命令完成，改状态和放弃通过任务操作菜单完成。

## 第四步：插件面板、任务属性面板、收集箱（已完成）

**目标**：有一个可用的主界面，能完成澄清。

- 编辑器工具按钮打开或关闭插件面板，全局最多一个：当前行只有一个面板时，在右侧打开并对半分；已有多个面板时，覆盖相邻面板，关闭时恢复（ADR 0011）。视图导航外壳。
- 任务属性面板：编辑状态、重要性、工作量、开始日期、截止日期、上下文、标记、备注。在任务操作菜单中接入"打开任务属性面板"。
- 收集箱视图：逐条澄清（改成其他状态、补齐属性、放弃）。
- 视图的查询、缓存与刷新机制（ADR 0007：按需查询，命令后钩子让缓存失效），之后的所有视图都复用这一套。

**完成标准**：可以在收集箱视图中把所有任务澄清完毕。

## 第五步：下一步行动、依赖与顺序执行（已完成）

**目标**：插件的核心价值：自动找出现在该做的事，并给出排序。原路线图的第五、六步合并为这一步：没有依赖和顺序执行，下一步行动不可信。

- `domain/blocking`：子任务阻塞、依赖阻塞、顺序阻塞、搁置子树、开始日期（含祖先任务的开始日期）与 `startPreviewDays`。
- `domain/scoring`：评分公式，参数写死，不开放设置。
- 依赖、依赖模式、顺序执行三个任务属性；在任务属性面板中选择被依赖的任务，并检测循环依赖。
- 失效依赖：放弃任务、编辑依赖时一并清除。
- 下一步行动视图：按上下文、标记、重要性、紧急度筛选，始终按评分从高到低排列，不提供其他排序。

**完成标准**：`GLOSSARY.md` 中每条阻塞约定都有测试；开始个人日常使用。

## 第六步：全部任务视图（已完成）

- 按块层级展示所有任务的树，可以按状态、上下文、标记、重要性、紧急度筛选，也可以搜索。
- 排序选项（按截止日期、重要性、紧急度等）放在这个视图，只调整顶层任务的先后，子任务始终按笔记中的顺序（默认顺序）。
- 已完成的任务放在默认折叠的已完成区，展开时才显示。数据与树共用同一次读取：阻塞判断本来就要读取已完成的任务，单独查询省不下什么。
- 在树中拖拽任务来移动块（ADR 0003 中的"插件可以提供命令辅助"）。动手前先实测 Orca 的移动与撤销。实测发现撤销不可靠时，拖拽推迟到以后的步骤，其余部分照常完成。

**完成标准**：每个未完成的任务都能在树中按块层级找到；排序、筛选、搜索、已完成区都可用；能通过拖拽调整层级和顺序，并且可以撤销。

## 第七步：我的一天（已完成）

- 把任务加入或移出我的一天（每个任务每个逻辑日最多一条记录；过去的记录保留，不顺延，ADR 0020）。任何任务都能加入，入口是任务操作菜单和视图中的搜索框。
- 我的一天视图：未排期区（按评分排列）与时间轴（覆盖整个逻辑日），按视图宽度左右或上下排列，占满视图高度。
- 排期：拖到时间轴上排期，拖动卡片改时刻，拖上下边缘改开始或结束，拖回未排期区取消排期；也可以用排期弹窗输入。吸附 15 分钟，默认 60 分钟，重叠的排期并排显示。

## 第八步：重复任务（已完成）

- 重复规则模型，支持多种自定义周期。
- 完成时记录完成历史，然后安排下一次：回到待开始，日期改成下次日期（ADR 0006）。下次日期从哪天往后算由重复方式决定：按固定日程或按完成日期。

## 第九步：回顾（已完成）

- 单个任务的回顾计划：回顾周期（按周、按月时可以指定回顾落点）和指定回顾日，标记已回顾，以及是否需要回顾的判断。
- 完整回顾：收集箱 → 回看过去 → 逾期任务 → 未来 7 天到期 → 下一步行动 → 等待中 → 将来/也许 → 需要回顾的任务 → 小结，每步都有快捷操作，步骤可以任意跳转。不做完整回顾时，也可以只看需要回顾的任务。

## 第十步：提醒（已完成）

- 根据第一步的验证结论和第十步的补测（`docs/spikes/native-reminder.md`），提醒由插件自己实现，不复用 Orca 原生提醒（ADR 0022）：一个任务可以有多个提醒，到时发出系统通知，错过的提醒在下次打开 Orca 时逐个补发。
- 任务属性面板中设定提醒，带以开始日期、截止日期为参照的快捷选项；提醒默认时刻在设置中修改。插件面板的任务卡片上显示铃铛。

## 第十一步：项目

**目标**：把一组任务归在一个想要的结果之下，看清手上有哪些项目、各自进展如何、哪个缺少下一步行动。调研见 `docs/research/project-management-tools.md`，表达方式见 ADR 0025。分五个阶段，每个阶段都能单独使用，开始前单独讨论细节。

不做：里程碑对象、阶段与阶段关口、基线、手填健康度、定期状态更新、子项目、项目之间的依赖、项目模板、资源与工作量。阶段用项目根任务表达，要依次推进时用依赖；项目本身的顺序执行另议；里程碑标记在甘特图布局阶段再议。

### 第一阶段：基础能力（已完成）

- 项目标签：创建、对齐、接管、改名、冲突处理复用任务标签的机制。属性：项目状态（五种，默认规划中）、目标、开始日期、截止日期、重要性、紧急度。项目属性先在 Orca 原生的标签属性中编辑。新建项目即在 Orca 中打项目标签，不提供"转为项目"。
- 任务标签新增所属项目（单值块引用）；所属项目按父任务优先判定。
- 项目对所属任务的约束：项目状态、项目开始日期进入下一步行动的判断，项目的重要性和紧急度参与评分；阻塞原因列出所属项目的原因。
- 项目操作菜单（右键点击项目标签）：切换项目状态、放弃项目。
- 进度、缺少下一步行动的计算。
- 全部任务视图中显示项目行；任务卡片在位置看不出所属项目时显示项目名。快速捕获可以选所属项目。
- 界面（原型 `.scratch/prototypes/step11-project-rows.html` 选定，2026-10-15）：
  - 项目行用标题式：不画卡片边框，一行是项目状态图标、加粗的项目名、进度百分比，下面一条细进度条；再下一行按需放"缺少下一步行动"（黄色标记）、未到时的开始日期、截止日期（逾期标红）。没有任务时写"没有任务"；有任务但没有计入的任务时不显示进度。页面项目和块项目在行上不区分。靠所属项目归属、不在项目块下面的任务，行上不另外标出。项目行默认折叠。
  - 点项目状态图标或右键项目行，弹出项目操作菜单（与右键项目标签相同）；点行的其余部分折叠或展开。
  - 项目下面已完成的任务淡化，留在原位，与树中其他已完成任务相同。项目状态为已完成、属于它的任务也全部完成时，项目连同任务进入已完成区，占一项；否则项目行留在树里，不淡化，行上标出"还有 N 个任务未完成"。
  - 卡片上的项目名放在文字上方那一行（父任务名的位置）：项目状态图标加项目名，有父任务时项目名在前、父任务名在后。全部任务视图中，只在任务不位于它的项目行下面时显示，它的后代任务不再重复显示；下一步行动视图中，属于项目的任务都显示。
  - 项目状态图标用文件夹一族：规划中 `folder`、进行中 `folder-bolt`、暂停中 `folder-pause`、将来/也许 `folder-question`、已完成 `folder-check`，颜色按任务状态图标的同类状态取。笔记中的项目块前同样显示；页面标题前能否显示，开工时实测。
  - 阻塞原因的两条新原因与祖先任务同一句式："所属项目 搬家 暂停中"、"所属项目 年底旅行 未到开始日期：10月20日 周二"。项目名可以点，在笔记中打开。
- 排序（全部任务视图）：项目行是一个顶层节点，与顶层任务一起排，每种排序取项目自己的值：截止日期、开始日期、重要性、紧急度取项目的；评分用同一个公式，工作量取默认值 4，没有祖先因子；捕获时间取项目块的创建时间。项目行下面的任务始终按笔记中的顺序。
- 筛选与搜索（全部任务视图）：项目行下面有任务通过时显示项目行，只列出通过的任务；一个都没有时隐藏项目行。项目行不是任务，不淡化。搜索文字匹配项目名时，显示项目行和它的全部任务（其余筛选条件照常作用）。状态筛选只看任务的状态，不看项目状态；匹配计数只数任务。有筛选或搜索时项目行临时展开，不改动保存的折叠状态。
- 任务属性面板的"所属项目"：与依赖字段同一套样式，只能有一个值。
  - 由父任务决定时，显示"搬家 · 来自父任务 装修方案"，只读，父任务名可以点。任务自己被覆盖的设定显示为划掉、标"不生效"，可以删除。
  - 由所在位置决定时，显示"搬家 · 来自所在位置"，可以改设；改设后自己的设定优先。
  - 自己设定或没有时，可以搜索、选择、清除。
  - 候选只列出未完成的项目，前面带项目状态图标。指向的块已不是项目时，划掉并标"已失效"，与失效依赖相同。
- 快速捕获：截止日期之后加一个可选的"所属项目"，候选与任务属性面板相同，默认为空，不记住上一次的选择。新任务仍追加到当天日记末尾；打标签和写所属项目在同一个撤销步骤中（`insertTag` 不能直接写块引用值，`docs/spikes/project-tag.md`）。
- 放弃项目：用 Orca 的确认框，"放弃项目"搬家"？其中 N 个未完成的任务也会被放弃，已完成的任务保留。可以撤销。"N 包括位于项目块下的任务和靠所属项目归属的任务；N 为 0 时不确认，直接放弃。所有指向这个项目的所属项目设定一并清除（已完成的任务也清），与放弃任务时清除依赖相同。
- 开工时实测：页面标题前的项目状态图标；快速捕获"打标签加写所属项目"的撤销；放弃项目的批量写入与撤销；项目标签改名后 `scope` 是否跟随；镜像块上的项目标签。

### 第二阶段：项目视图与层级布局（已完成）

- 项目视图：导航中排在全部任务视图之后、回顾之前，图标 `folder`，不显示数字。各档宽度都是先进项目列表、点开一个项目进项目详情，不分栏。详情顶部有"‹ 项目"返回按钮；在详情中再点导航中的项目视图，也回到列表。打开的是哪个项目保存在插件实例的内存中，切走再回来仍停在详情；项目被放弃或不再是项目时退回列表。这一阶段不做从别处打开项目详情的入口，项目操作菜单不变。
- 项目列表：按项目状态分组，依次为进行中、规划中、暂停中、将来/也许、已完成；组头显示个数，已完成组默认折叠，全部列出。组内按项目的评分排列（与全部任务视图中项目行的"按评分"相同），不提供排序选择，不加搜索和筛选。每个项目用第一阶段的项目行，已完成但还有未完成任务的项目标出"还有 N 个任务未完成"。点行进入项目详情，点项目状态图标或右键弹出项目操作菜单。
- 项目详情的属性区（原型 `.scratch/prototypes/step11-project-view.html` 方案 C 选定，2026-10-16）：只读。项目状态图标、项目名、进度百分比一行；开始日期（到没到都显示）、截止日期、缺少下一步行动、非默认的重要性和紧急度挤在一行；目标折成一行，点开显示全部；进度条压在属性区底边。点项目状态图标弹出项目操作菜单，点项目名在笔记中打开，属性仍在 Orca 原生的标签属性中编辑。
- 项目详情的层级布局：列出属于这个项目的全部任务（按所属项目，不论写在笔记的哪里；位于项目块下、却属于别的项目的任务不在其中）。树的根是父任务不属于这个项目的任务，默认按笔记中的顺序；卡片上不显示项目名，根任务有父任务时照常显示父任务名。筛选、搜索、排序（只调整根的先后）、已完成区（含近 30 天的规则）、折叠、全部折叠、拖到笔记、树内拖拽都与全部任务视图相同，状态与全部任务视图分开保存：换一个项目时清空筛选、搜索和排序，折叠状态按任务记住。树内拖拽跨越项目块的边界时（被拖的任务和落点一个位于项目块下、一个不在），先用 Orca 的确认框说明移动后的结果，确认后才移动，可以撤销：仍属于这个项目时，写明会挪进或移出项目块；不再属于任何项目、或会属于另一个项目时，写明它会从这里消失。移动后的归属按所属项目的规则推算。本来就会被拒绝的移动（如造成循环依赖）不弹确认，照常提示；不跨边界的移动不确认；全部任务视图不确认。这一阶段只有层级一种布局，不显示布局切换。

### 第三阶段：回顾（已完成）

- 回顾中新增"项目"一步，排在等待中之后、将来/也许之前（GTD 每周回顾的顺序）。逐个检视项目，不只看有问题的：列出未完成的项目，以及已完成但还有未完成任务的项目；分组、组内排序与项目列表相同（进行中、规划中、暂停中、将来/也许、已完成，组内按评分），不加筛选和搜索；已完成组默认展开（这里只有还有未完成任务的项目），折叠状态与项目列表分开保存。将来/也许的项目在这一步，"将来/也许"一步仍只列任务。每个项目用项目行。项目标签暂停时与项目视图相同，显示暂停的提示；没有项目时显示空状态"没有项目"（图标 `folder`）；两种情况下这一步都照常可以打开，"上一步 / 下一步"不跳过它。计数与其他步骤相同，只算属于这一步的项目，不算淡化后留在原位的。
- 这一步的快捷操作：点项目状态图标或右键弹出项目操作菜单；点行的其余部分跳到项目视图并打开这个项目的详情（第一个从别处打开项目详情的入口；详情的"‹ 项目"仍回项目列表，回顾的进度留在内存中，点导航回到回顾仍停在这一步）；行第一行右端的"创建任务"图标按钮（与回顾卡片的图标按钮相同）打开快速捕获，所属项目预填为这个项目，可以改或清除，只对这一次有效。已完成组的项目行也有这个按钮。
- 在这一步中改了项目状态：仍在这一步的项目移到新的组；改成已完成、任务也全部完成而离开这一步的，淡化后留在已完成组，切到别的步骤才消失；被放弃的直接消失。
- 两个新信号（GLOSSARY: 长期无进展、逾期项目）：
  - 长期无进展：进行中、已到开始日期（计入 `startPreviewDays`，与缺少下一步行动相同）的项目，最近一次进展所在的逻辑日之后满 14 个逻辑日。最近一次进展取属于它的任务最后一次完成、属于它的任务的创建时间、项目块的创建时间、项目的开始日期中最晚的。14 天写死。行上显示"N 天无进展"，用缺少下一步行动的黄色警示样式。
  - 逾期项目：只看项目自己的截止日期。项目行上日期标红之外，再加"逾期"字样的警示标记；项目里的逾期任务不在行上另外计数，它们在"逾期任务"一步。
  - 两个信号显示在所有项目行（全部任务视图、项目列表、回顾的"项目"一步）和项目详情的属性区，与缺少下一步行动相同。
- 小结新增两行："缺少下一步行动的项目"、"长期无进展的项目"。
- 不做：项目的回顾周期和标记已回顾（"项目"一步每次都列出全部项目）；统计视图页头和导航中回顾的数字不加项目信号。

### 第四阶段：看板布局

原型 `.scratch/prototypes/step11-project-board.html` 选定（2026-10-16）。

- 布局切换：项目详情工具栏最左边是分段切换"层级 / 看板"（只有图标），选看板时旁边再出"按状态 / 按根任务"（GLOSSARY: 分列方式）。两个选择记在插件实例的内存中，所有项目通用。设置中新增"项目视图默认布局"（层级、看板，默认层级，以后可以加），插件加载时按它决定布局；在设置中改了立即生效，覆盖内存中的选择。分列方式不进设置，默认按状态。
- 按状态分列：六列固定为收集箱、待开始、进行中、等待中、将来/也许、已完成，空列也保留作为落点，列头显示个数。卡片是项目根任务。已完成列默认收成一条窄边，点开恢复正常宽度，沿用已完成区近 30 天的规则，更早的再点开。
- 按根任务分列：最前面一列"其他"放没有子任务的项目根任务；其余每个有子任务的项目根任务占一列，卡片是它的直接子任务。列头是项目根任务本身：状态图标（点开状态菜单）、任务名（点开任务属性面板）、阻塞时的锁、"已完成/直接子任务数"，右键弹任务操作菜单。列的顺序固定为笔记中的顺序，列头不能拖。每列底部"已完成 N"默认折叠，点开列出淡化的已完成卡片，不限 30 天。项目根任务自己和全部后代任务都已完成时，这一列收成窄边，排在所有列之后，点开恢复。最后一个子任务被移走后，它回到"其他"。
- 排序：选项与层级布局相同，默认评分，与层级布局的排序分开保存；不做手动排序。排序只决定列内卡片的先后；卡片内的子任务、按根任务分列时列的先后，始终按笔记中的顺序。已完成的卡片按完成时间从新到旧，不跟随排序。
- 卡片：沿用任务卡片，多两样。下一步行动在状态图标右上角显示一个小点，只在看板中有。有子任务时属性行下面加"子任务 已完成/总数"（只数直接子任务）和折叠按钮；折叠时，后代任务中有进行中或下一步行动的，跟着显示"进行中 N · 下一步 N"，为 0 的不显示。展开后列出全部后代任务，带缩进，每个一行紧凑的行：状态图标、任务名、阻塞时的锁、下一步行动的小点；点状态图标改状态，点行打开任务属性面板，右键弹任务操作菜单。看板的折叠状态单独保存，按任务记、默认折叠、在内存中；工具栏有"全部折叠 / 全部展开"。
- 拖动（卡片和展开后的子任务行都能拖，第十三步的统一拖法，也能拖到笔记）：
  - 落在列的空白处：按状态分列时只改状态，不移动块，子任务改完状态仍留在原来的卡片里；按根任务分列时成为这个项目根任务的最后一个子任务。整列高亮。
  - 落在一张卡片或一行子任务上：成为它的最后一个子任务，状态不变。目标描边高亮，放下后目标卡片自动展开。
  - 成为项目根任务：按状态分列时，拖动非根任务时最右边出现"作为根任务"的虚线落点；按根任务分列时拖进"其他"。都移到项目块末尾。
  - 拖到自己、自己的后代、原来的父任务上不算落点，回退到所在的列；落回原来的列什么都不做。
  - 改状态走现有的改状态逻辑（完成历史、重复任务安排下一次并回到待开始、清除提醒）；被阻塞的任务拖进进行中、有未完成子任务的拖进已完成都不拦截。移动块复用层级布局的移动：可以撤销，循环依赖照常拒绝，跨项目块边界时沿用第二阶段的确认框。一次拖动只做一次写入，不做"改状态加移动"的组合。
  - 拖到看板左右边缘时横向滚动，拖到列的上下边缘时列内滚动。
- 宽度与滚动：看板区单独允许横向滚动，列宽约 260px，带滚动吸附；窄档一列约占视图宽度的 85%，露出下一列的边。看板时属性区和工具栏固定在上方，看板占满剩下的高度，各列各自纵向滚动；层级布局仍整页滚动。
- 筛选与搜索：与层级布局共用，换布局不清空。卡片在自己或任一后代任务通过时显示，展开后只列通过的子任务。按状态分列时状态筛选只决定显示哪几列；按根任务分列时，项目根任务本身通过或里面有卡片通过的列才显示。有筛选或搜索时，空列、"作为根任务"、空的"其他"都隐藏。
- 新建任务：看板工具栏的"创建任务"图标按钮打开快速捕获，所属项目预填为这个项目（与回顾"项目"一步的按钮相同）。新任务仍追加到当天日记末尾、处于收集箱。不做每列底部的"+"。
- 不用拖动时：改状态用状态图标或右键菜单；移到别的任务下面只能拖，等"待排期的想法"里的"移动到…"再补。
- 不做：手动排序、泳道、拖动列头、多选与批量操作、子任务阻塞计入卡片上的阻塞标记。

### 第五阶段：甘特图布局

## 第十二步：自定义属性（已完成）

- 允许用户给任务添加自定义属性（文本、数字、布尔、日期、日期时间、时间、单选、多选、块引用）。定义的增删改（含默认值、选项）在 Orca 自带的任务标签属性界面中完成，插件不另设管理入口（ADR 0023）；插件读取定义，在任务属性面板中查看和编辑值（各类型仿照面板里已有的同类字段，单选、多选可以直接输入新选项）。不按自定义属性筛选和排序，改为增强搜索：搜索匹配任务文字加上 Orca 为块维护的 `text`（块文字、标签和标签属性的值，含块引用目标的文字），自定义属性的值因此也能搜到。全部任务视图、我的一天的加入任务、选择依赖三处搜索共用这一规则；内置属性的值（状态名、数字、日期）同样会被搜到，不剔除。下一步行动视图不加搜索框，占位文字不变。
- 顺带修复：文本属性的值可能存成数字（`custom-properties`），"备注"读作字符串，不再读成空值。

## 第十三步：拖拽任务卡片到笔记（已完成）

- 统一拖法：所有视图的任务卡片都改成按住卡片任意处、移动几个像素后开始拖（我的一天的做法），单击、按钮、右键菜单不受影响。全部任务视图去掉拖动手柄，卡片文字不再能选中。
- 拖拽的含义由落点决定：插件面板内保持原有行为（移动块、排期），落到笔记面板的块上则写入指向任务的引用或镜像，落在别处取消。一次只拖一个任务。
- 默认写引用，松开时按住 Alt（Option）写镜像，不弹菜单，不显示提示文字。引用落在块的文字上时插在行内，落在块那一行的上下边缘时在前后新建一个只有引用的块；镜像只看上下半区，总是在前后新建镜像块。落在日记或页面的标题上时，作为它的第一个子块；落在展开了子块的块的下边缘时，作为它的第一个子块。插件自己画插入线（新建块）和插入光标（行内）。拖动时原卡片变淡，指针下跟一个显示任务名的小标签；指针靠近笔记面板上下边缘时面板跟着滚动。时间轴卡片只有拖本体才能拖到笔记，上下边缘仍只改起止时刻；任务属性面板、依赖选择列表、我的一天加入任务的搜索结果里的任务不能拖。
- 只写指向任务的引用或镜像，不改变任何任务关系（父子、依赖）。循环镜像交给 Orca 处理。
- 写入经过落点所在的笔记面板，撤销记在那里（ADR 0024）；写完后光标停在引用之后，或镜像落点块的末尾。实测结论见 `docs/spikes/drag-to-note.md`。

## 第十四步：统计视图（已完成）

**目标**：用图表回看一段时间里做了什么，并用几个关键数字看清此刻的状况。

- 插件面板中新增一个视图，排在回顾之后。以历史趋势为主，基于完成历史；不按上下文、标记筛选，统计全部任务。
- 按统计周期查看：周、月、年三档，可以前后翻；周和月按天细分，年按月细分，都按逻辑日算。坐标轴显示整个周期，未到的日子留空；往前翻不限，往后最远到当前周期，翻走后显示"回到本周（本月、今年）"。图表上方显示周期内的完成次数和跳过次数，不与上一个周期比较。
- 完成的计数（GLOSSARY: 统计视图）：重复任务按完成记录，每条一次；其他任务只看现在是否已完成，算一次。只统计插件记下的数据，不为统计新增记录，也不估算 Orca 原生界面中改成已完成的任务。
- 两张图：完成次数（柱状，跳过叠在上方）；完成的分布（上下文、标记、重要性的横向条形图，多值的每个各计一次；上下文、标记按次数从多到少，最后是"未设"，重要性固定七档）。不做我的一天的计划与完成、新建与完成的对比（块的创建时间不是捕获时间）、全年热力格。
- 点击完成次数图的某一天（年档为某个月），或完成的分布中的某一项，在下方列出相应的完成与跳过，最新的在前，重复任务完成几次列几次，跳过的标为已跳过；卡片行为与其他视图一致。一次只选一项，再点一次取消；未选时只显示提示，不默认列出整个周期。分布图始终显示整个周期，不随选中的那天变化。
- 页头四个当前状况的数字：下一步行动、进行中、等待中、逾期，与统计周期无关。点击跳到对应的视图（进行中、等待中跳到按状态筛选的全部任务视图，逾期跳到回顾的逾期任务一步），这需要插件面板提供从一个视图跳到另一个视图的能力。
- 响应式、灵活布局，三档宽度下都自上而下：页头数字（窄档两行两列，其余一行）、周期切换、完成次数图（占满宽度，日期标签按宽度稀疏显示，悬停显示日期和次数）、完成的分布（上下文、标记、重要性用分段切换，默认上下文）、选中项的列表。所选档位保存在插件实例的内存中，与其他视图的筛选一样，不写 `plugins.setData`。
- 图表用 SVG 自己画，颜色取 Orca 的主题变量，不引入图表库。
- 周期内没有完成和跳过时，照常画坐标轴并说明没有记录，分布处只显示同一句说明；读取中、读取失败、暂停复用其他视图的提示。
